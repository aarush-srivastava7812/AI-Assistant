Research performed 2026-10-29 using the local REA CLI. Targets were analyzed statically; no target application was executed and no vendor UI code, branding or visual assets were incorporated into Wayfinder.

REA inputs, commands, stdout, errors and execution records are retained locally under `.local/onboarding-research/`. AnythingLLM source acquisition also records the immutable URL, byte count and SHA-256 for each selected file. The selected scopes omit most of each application. Static routes and literals do not establish native permissions, backend enforcement, live account consent or usability; Wayfinder's own tests cover its implementation separately.

Official reference material: [AnythingLLM model configuration](https://docs.anythingllm.com/setup/llm-configuration/overview), [AnythingLLM Windows installation](https://docs.anythingllm.com/installation-desktop/windows), [VS Code workspace trust](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust). VS Code was a documentation reference only, not a REA target in this work.

Wayfinder's choices are separate persisted booleans for pet, chat widget and advisory task agents, defaulting off. Folder choices use a native picker; they do not trigger automatic scanning. Removing a saved folder revokes current file grants before saving that removal. Agent opt-out blocks new task dispatch and retries in main; existing runs retain explicit Stop controls. The widget toggle destroys its window and unregisters its shortcut, independently of the pet.

Google sign-in uses the system browser, a main-owned IPv4 loopback listener, random state and PKCE S256. The user supplies a Google Desktop client JSON and selects read-only services. Tokens stay in the encrypted main-process connection vault. [Google's desktop loopback guidance](https://developers.google.com/identity/protocols/oauth2/resources/loopback-migration) and [official Windows OAuth sample](https://github.com/googlesamples/oauth-apps-for-windows/blob/master/OAuthDesktopApp/README.md) informed this flow. No app-owned Google client or live Google consent is claimed.

The installer bundles the Python application backend and memory model. Its dependency bootstrap installs the pinned official Hermes SDK and private Python environment using the upstream frozen lock, and invokes Docker Desktop's interactive installer through winget when Docker is absent. It does not silently accept Docker's license, change the default WSL distribution, or reset other Docker services. [Docker Windows requirements](https://docs.docker.com/desktop/setup/install/windows-install/) still apply; virtualization, Windows permission prompts and restarts cannot be removed by onboarding. [Hermes installation documentation](https://hermes-agent.nousresearch.com/docs/getting-started/installation/) and its pinned source are the runtime references. The application qualifies actual signatures, history support, tools-closed behavior and memory isolation before enabling model use.

## OpenCode chatbot

The user's final choice is OpenCode for the chatbot, with credentials supplied by each user. Chat uses the pinned official **OpenCode 1.19.5** Windows baseline executable; advisory source workers continue to use Hermes. No developer key is included in either artifact.

REA analyzed five selected TypeScript boundaries at OpenCode commit `810c0eba1a7348036f8bdf61e6632d0c36c6876c`: authentication, global profile paths, permission evaluation, session routes and CLI session import. The analysis completed successfully in 12.25 seconds with evidence **`ev_e66f0ffa7bd7361e146e1703a2d7650306e4721b525a0c983c5670bb81adfaa7`**. Commands, exact source hashes, selected paths and raw evidence remain under `.local/opencode-research/`. This is scoped static source evidence; the actual binary was separately acquired from the matching official release and checked against its published SHA-256.

The [official server interface](https://opencode.ai/docs/server/) supplies authenticated loopback sessions, model prompts and cancellation. Wayfinder starts a fresh private profile per turn and restores only its bounded completed user/assistant pairs through OpenCode's supported import command. It verifies those exact messages through the server before requesting the next reply. It does not implement another model inference loop. The canonical conversation records, idempotency and interrupted-turn behavior remain in Wayfinder.

The adapter uses a single approved NVIDIA provider and the user's encrypted local key. Keys reach OpenCode through its process environment, without credential files or command-line arguments. XDG directories, home, temp and managed config paths are isolated; project configuration, default plugins and external skills are disabled. Agent-wide and session-wide permissions deny all tools; the session rule is checked before dispatch. Sharing and helper agents are disabled. A real NVIDIA canary confirmed an initial reply and a second reply using restored canonical history. Static analysis alone was not used to assert these runtime results.
